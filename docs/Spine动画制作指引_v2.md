# Spine 动画制作指引 v2

适用于二维角色的骨骼动画、多角度换图、持物动作及游戏接入。本文包含完整制作流程、必要概念和验收方法，可独立阅读。

**制作顺序：动作需求 → 参考姿势与时间表 → 素材检查和拆件 → 骨架与姿势绑定 → 主动作 → 换图与中间过程 → 跟随与细节 → 画面和数据验收 → 导出交付。**

动作是否成立，首先看姿态、透视、重心、节奏与表演。数值检查用于发现结构和接入故障，不能代替视觉判断；参考图有误时，应先修绘图，再继续绑定。

## 1. 基本概念与方法选择

| 概念 | 含义与用途 |
| --- | --- |
| 骨骼（Bone） | 通过父子层级组织位置、旋转、缩放等变换，是动作控制结构。 |
| 插槽（Slot） | 关联骨骼并承载当前显示的附件；一个槽可准备多张附件，但同一时刻只显示其中一张，也可以不显示。 |
| 附件（Attachment） | 槽中的具体内容。区域附件（Region）作为整体图片变换；网格附件（Mesh）可通过顶点、权重和变形表现局部运动。 |
| 皮肤（Skin） | 按槽组织一组附件映射，用于外观组合；不等同于一个动画，也不保证每槽只有一张图。 |
| 网格、权重与绑定姿势 | 网格把图片划分为三角形；权重决定顶点受哪些骨骼影响；绑定姿势规定建立这些影响关系时骨骼和网格的位置。 |
| 时间线与关键帧 | 分别记录骨骼变换、网格变形、附件选择、绘制顺序和事件等变化；这些通道需要分别管理。 |
| 绘制顺序（Draw Order） | 控制槽的前后遮挡，与骨骼父子关系不同；转身时可随动作变化。 |
| FK / IK | FK 直接控制关节旋转，适合设计运动弧线；IK 由末端目标反求关节姿势，适合握持和接地约束。 |

| 制作方法 | 适合处理 | 使用边界 |
| --- | --- | --- |
| 骨骼平移、旋转 | 同一视角中的摆动、点头、重心移动 | 不能把正面图直接变成侧面图。 |
| 蒙皮网格变形 | 袖口、裙摆、布料和有限的体积变化 | 不宜把站姿强拉成趴姿，或用全身变形扭曲五官。 |
| 同槽附件切换 | 手型、表情、肢体翻面和不同透视 | 必须维持部位身份、关节锚点、体积与轮廓连续。 |
| 独立姿势绑定 | 前倾、坐跪、撑地、趴地及强透视 | 优先复用骨架，为必要部件保存不同绑定姿势，避免每个角度复制整套骨骼。 |

这些方法可以混用。大动作既可以在同槽换图，也可以显隐一组专用姿势部件。统计多附件槽的数量不能代表全部替换图数量，还应检查皮肤、独立槽和显隐时间线。

## 2. 先明确动作，再画参考姿势

每个动作先写清：起止姿势、动作意图、阶段与预计时长、停顿或经过姿势、支撑点、握持关系、事件时刻、循环或保持方式，以及允许被哪些动作打断。

先画能说明动作的关键姿势，再补连接它们的分解姿势，并为每张图标注时间。绘图频率、时间线帧率、数据采样率和运行时刷新率是不同概念；每秒采样 60 个数值不等于设计了 60 张参考图。

参考图逐张与连播都要通过以下检查：

1. **数量正确。** 肢体和道具数量符合角色设定，没有重复手臂、残留道具或多余轮廓。
2. **身份连续。** 左右按角色自身定义；非对称服饰、标记和持物手不随画面方向交换。被透视遮住与被错误删除要区分。
3. **尺度统一。** 固定相机、地平线、角色比例和道具尺寸；禁止逐帧自动居中、缩放来隐藏漂移。
4. **承重合理。** 明确支撑脚与摆动脚，先建立支撑和重心转移，再解除原有接触；不能用脚踝骨贴地代替鞋底贴地。
5. **握持可信。** 同时检查手掌、握点和道具两端。刚体的长度和握持位置稳定，真实透视改变时才使用对应角度图。
6. **过程可读。** 中间姿势沿合理轨迹连接前后动作，不能只追求单张图好看。

保存原始参考图、姿势编号、时间表、锚点标注和淘汰原因；生成图片还应保存提示词、参数与实际输入。先做一个完整动作，确认方法可用后再扩展动作集。

## 3. 素材检查、角度变体与拆件

### 3.1 原尺寸纹理检查

新生成、重新生成或继承使用的参考图、部件图和道具图，都应在切图、绑定和图集打包前检查周期网格、摩尔纹、颗粒及鳞片状伪影。

1. 保留原图并记录哈希，在原尺寸下诊断；不要先缩放、压缩或截图。
2. 查看诊断热点和原生像素局部对比，区分伪影与真实的布纹、装饰、发丝。
3. 只处理确认有问题的区域，从较弱强度开始；未发现目标伪影时记录“已检查，保留原图”。
4. 对比轮廓线、头发、眼睛和衣服细节，拒绝模糊、缺失或新边缘。透明部件的纹理清理不得改变 alpha，应逐像素比对。
5. 保存工具版本、输入与输出哈希、诊断数据、处理参数、对比图和采用结论。无法区分真实纹理与伪影时转人工复核，不盲目增强滤波。

任何图片像素变化都会使旧检查记录失效；应更新相应记录、重新打包图集，并复查动画和目标引擎渲染。

### 3.2 按动作准备变体

| 部位 | 常见变体 | 校准重点 |
| --- | --- | --- |
| 头脸 | 正面、三分之二侧面、侧面、低头、倒地角度 | 颈根、下巴、眼线、可见体积；禁止压扁正脸冒充侧脸。 |
| 头饰 | 转向、俯仰、倒地角度 | 与头顶的连接及边缘透视。 |
| 躯干与衣裙 | 正面、侧转、前倾、坐跪、撑地、趴地 | 肩、腰、髋、衣摆落点及胸背朝向。 |
| 上臂与袖 | 下垂、内收、前举、透视缩短、支撑 | 肩肘连接、袖根重叠及前后面。 |
| 前臂与手 | 张掌、握持、翻面、伸出、撑掌 | 腕部、手指完整性、拇指方向、掌背及握点。 |
| 腿与鞋 | 迈步、屈膝、跪撑、伸腿 | 膝踝、服饰归属、鞋底接触与裙摆遮挡。 |
| 头发与布料 | 站立、转身滞后、前倾、落地覆盖 | 根部固定关系、重力方向、运动滞后和穿插。 |
| 表情 | 专注、口型、用力、受击、疲惫 | 局部替换时保持脸宽、眼位和头部体积。 |
| 道具 | 主刚体图及必要透视角度 | 长度、厚度、握点和两端位置。 |

变体数量由新露出的表面、遮挡与变形需求决定。图片画布尺寸可以不同；需要衔接的是关节位置、可见体积和轮廓，不能机械地给所有部位准备相同数量的图。

### 3.3 拆图与布局

部件应有透明背景、明确枢轴和足够的关节重叠。补画被遮挡的肩、肘、腰、髋及衣服内侧；完整姿势不能只切成互不重叠的拼图，否则旋转后会露洞。手掌切片应包含完整手指，并清除低透明度残影和无关碎片。

保留原始画布、裁切矩形、裁切偏移、原尺寸、旋转、锚点和层级映射。自动分件若使用亮度阈值或连通域，须检查白色衣物、眼白、细饰物是否被当成背景或碎片。自动分件不能补出原图中不可见的内容。

生成补画或替换部件时，同时提供整角色参考和对应部件，明确风格、轮廓、位置、尺寸、旋转及数量约束。保存生成工具实际接收的输入与布局映射；提示词只表达要求，结果仍需逐项验收。

## 4. 骨架、坐标与接触约束

基础层级可采用：整体根骨 → 骨盆 → 胸腔 → 颈与头；双臂分别保留肩、上臂、前臂与手，双腿保留髋、大腿、小腿与脚。头发、布料及饰物使用必要的辅助骨。

二维骨长是屏幕投影。透视缩短时允许调整子骨位置，但应配套角度绘图；不能同时要求投影长度绝对不变和真实转身，也不能用整体横向缩放代替透视。

明确世界、骨骼局部、图片和屏幕坐标。一般的父子转换为：

```text
子节点局部点 = 父节点世界变换的逆矩阵 × 目标世界点
```

只有父节点不含旋转、缩放、剪切等线性变换时，才可直接用世界位置相减。Spine 通常采用 Y 向上的坐标，而图像和部分屏幕坐标 Y 向下，转换时应显式处理。

握物、脚踩地和手撑地分别设计约束。接触阶段保持接触点在世界坐标中稳定，解除接触后再恢复自由运动；身体根骨移动时尤其要防止支撑点被一同带走。IK 与 FK 可分阶段混合，但切换前应对齐姿势。肘膝改变弯曲方向需有伸直或透视翻面的过渡，不能在深屈曲时直接跳到另一解。

持物时确定手和道具谁是主控制者，避免互相驱动；双手握同一物体时分别约束两个握点。不要拉长道具来迁就手的位置。

## 5. 多姿势绑定与权重

### 5.1 新增姿势的操作顺序

1. 以目标姿势绘图为基准，建立新附件和必要网格；沿轮廓、关节及表面分界布点，先保持结构简洁。
2. 将新增附件归入正确槽；合并到已有骨架时保留原网格，检查未匹配名称是否产生了错误的新槽。
3. 将新网格临时绑定到在此过程中保持不动的骨骼，使调整其他骨骼时图片位置保持稳定。
4. 在动画模式创建专用绑定姿势，例如 `bind/turn`、`bind/brace`。显示目标附件，将骨骼对齐绘图的关节和透视。
5. 在此姿势下重新绑定到实际控制骨骼，解除临时骨骼影响，再调整权重。已有绑定若基准不正确，可用 `Update Bindings` 按当前骨骼和网格位置更新。
6. 保留绑定姿势，复制一份测试其运动范围。辅助绑定动画用于编辑，交付运行时资源时应按约定排除。

若修改权重时顶点突然跑位，先检查当前姿势与绑定姿势是否不同，不要不断补偿位移。在其他姿势绑定的附件回到设置姿势时可能显得异常，应回到它的绑定姿势判断；不能把站姿绑定的大幅变形当成正确的趴姿绑定。

### 5.2 防止错误牵连

- 权重影响应有明确的部位边界。不要把肩、腕、膝等大量控制点无区别地放进同一个全身网格；肢体在二维投影中交叉时可能牵扯无关衣服和腿部。
- 头脸及稳定握持部位可使用刚性或局部绑定，避免身体变形拉伸五官；同时保留颈部、腕部连接，不要只校准部件中心。
- 袖口、腰和髋的局部网格应保留重叠，并共同检查接缝；按槽独立绑定不代表接口自动连续。
- 增减顶点优先回到保存的绑定姿势操作，再到实际变形姿势调整权重；检查全部受影响动作，避免修好一帧却破坏其他姿势。
- 大幅转向可把躯干理解为若干可见表面，通过前后肩的位置和局部权重改变各表面的可见宽度；新露出的背面仍需对应绘图。

## 6. 附件切换与遮挡

先在预定切换姿势分别显示旧、新附件，对齐关节锚点、可见体积、轮廓和内部线条，再决定换图时间。头部要同时看颈根和眼位，手部要同时看腕部与握点。

切换通常适合安排在遮挡变化、运动较快或两侧轮廓接近的位置，但这不能掩盖错误绘图。切换键不必位于两张参考姿势的正中间；应比较两侧网格在过渡姿势中的变形，选择稳定时机，避免来回切换。

多角度转身可先让前后附件分别向接近侧面的姿态过渡，在该切换姿势修权重和轮廓，再完成后半段转向。差异仍大时补中间角度图；仅统一大小不足以保证帽檐、衣纹和裙摆连续。

附件键、骨骼变换、网格变形与 `drawOrder` 应协同设置。不同部位可在不同时刻换图，不必由一个全身姿势开关一起切换。独立槽显隐要检查旧部件已隐藏且新部件没有重叠残留。淡入淡出只适用于确实需要混合轮廓的表现，不能作为默认补救，否则容易出现双眼、双轮廓或重复道具。

每个动作入口应显式设置必要附件、绘制顺序和约束状态，或由经过验证的统一复位逻辑完成，防止上个动作留下的手型、背面部件或死亡姿势泄漏。实际播放的混合过程也须检查。

## 7. 主动作、节奏、弧线与跟随

### 7.1 先安排时间和空间

**时间间隔**决定阶段耗时，**空间间隔**决定等时间内移动多远。先以少量主姿势组织准备、发力、跟随和收住，再补连接姿势；不要一开始铺满关键帧并逐段精修曲线。

将姿势标成“停顿、接触、反向、经过”。经过姿势应保持合理速度，真正的承重、停顿和撞击则需要明确表现。对每段统一套缓入缓出，会把经过姿势也变成停靠点。例如 `s(u) = u²(3−2u)` 在两端的导数均为零，逐段使用容易产生机械启停。

保持、线性和贝塞尔曲线分别适合离散停留、匀速区间和需要控制加减速的区间，应按动作选择。曲线图中横轴为时间、纵轴为属性值；局部斜率可帮助定位速度变化，但父子变换、IK 和多通道组合会影响最终画面，曲线漂亮不等于动作自然。

### 7.2 弧线与重量

在固定相机下追踪头、胸、骨盆、双手、脚底和道具尖端，标出等时间间隔的位置点。检查是否出现不必要的速度谷、折向、停顿或滑动。对每个骨骼使用同一进度进行世界坐标直线插值，只能连接端点，不能自动产生自然弧线。

重心、支撑和发力要有因果：先取得支撑，再抬起或转移重量；落地有缓冲，起身有承重转换，停止时有收势。可以按风格夸张，但不能让承重掌随胸腔滑走，也不能让支撑脚无故漂移。

### 7.3 跟随、重叠与波浪

先做好主动作和重心，再处理头、肩、肘、腕等部位的先后关系。各部位可以错开启动和到达时刻，错开的量由惯性、材质和动作意图决定，不能统一延后若干帧。

布料、头发和柔软饰物可从根部到末端传递弯曲，主体停下后继续少量运动并逐渐收住；检查重力、碰撞及穿插。刚性道具不套用这种波浪变形。循环动画偏移关键帧后，应重新检查起点、终点及速度衔接。

### 7.4 常见动作的设计重点

| 动作 | 需要明确的过程 |
| --- | --- |
| 进入准备或持物姿势 | 从真实起点出发，安排视线、头、肩髋与手臂的先后，沿合理弧线到达终点。 |
| 持续准备与释放 | 稳定状态只保留必要呼吸和局部表演；释放有蓄力、发力和收住。逻辑效果多次触发不应意外重复整段身体动作。 |
| 失衡与倒地 | 从前一终姿卸力，依次改变支撑与身体朝向；最终胸背朝向要由全过程自然到达。 |
| 起身 | 从真实倒地姿势开始，逐步建立手脚支撑、调整膝髋和重心，站稳后回收肢体与道具。 |
| 受击与死亡 | 按站立、坐跪、倒地等基础状态准备必要变体，不能突然重置为站姿；最后的保持姿势要与前段连续。 |
| 循环与动作衔接 | 检查位置、速度、附件、层级和约束；循环、非循环及末帧保持由播放逻辑明确设置。 |

## 8. 自动化辅助的范围

自动工具适合初始布局、重复导出、数值筛查和修正记录。预设动作只能作为草稿，不能直接照搬骨骼名、角度、时长或缓动。

| 环节 | 可用流程 | 必须复核的边界 |
| --- | --- | --- |
| 部件定位 | 对同一绘图的透明部件做前景遮罩，用 SIFT 特征匹配与 RANSAC 估计相似变换；特征不足时尝试模板匹配。 | 独立生成或视角不同的图可能无法匹配。保存得分、内点数、采用方法及重组对照；低置信度改用人工关节标注。 |
| 匹配筛选 | 限定合理的旋转、缩放与位置范围，复核错误匹配。 | 确认工具是否搜索旋转；仅缩放和平移的回退不能处理任意转角。Lowe ratio 阈值调低会更严格，不能误当成放宽。 |
| 重组预览 | 按估计变换恢复部件布局。 | 必须实际应用旋转、缩放及偏移；只按包围盒贴图会掩盖定位错误。 |
| 遮挡建议 | 根据图像重叠推断前后关系。 | 像素投票或深度分数不保证消除冲突，也不等于拓扑排序；动态遮挡仍需编辑和验收。 |
| 骨架生成 | 把布局转换为骨骼、槽、附件与动画。 | 自动定位不等于绑定。中间还要明确关节、父子关系、坐标空间、附件偏移、命名映射及姿势绑定。 |
| 交互修正 | 提供暂停、逐帧、选槽、精确参数输入与记录导出。 | 固定相机并使用匹配版本的 Spine 运行库；近似绘制的骨架预览只能辅助定位问题。 |
| 换皮与补画 | 保留原骨骼、约束和动画，逐项替换外观。 | 遍历每个皮肤、槽和附件，不能只取每槽第一张图。核对尺寸、UV、裁切偏移、alpha 和全部动作。 |

编排工具链前先核对每一步的输入、输出和固定版本实现。模板说明可能滞后；“使用贝塞尔”或“自动生成”不构成质量保证。生成结果先做原尺寸检查，再进行交付所需的尺寸转换。

离线预览需将数据、纹理和固定版本运行库一并本地化，并实际断网验证；只内嵌图片、仍从网络加载播放器的页面不算完全离线。引入第三方代码或素材时记录来源与许可条件，不能默认所有公开仓库都采用宽松许可，也不能把仅供研究的素材混入交付图集。

## 9. 程序化生成与 Spine 4.2 格式

以下格式规则专指 Spine 4.2 的骨骼动画时间线。编写格式可以采用更易读的阶段和归一化缓动，但应通过明确、可验证的转换层输出运行库格式；不要把其他版本示例或通用 CSS 缓动数组直接写入。

- `rotate` 的角度值字段为 `value`，不能沿用旧格式的 `angle`。
- `curve` 描述当前键到下一键的区间，写在区间起始键上。如果内部约定把曲线放在目标键，仅在导出时前移一次；合规 JSON 不可重复转换。
- 贝塞尔控制点为绝对时间和该属性的值。一个属性用 4 个数值；同时控制 x/y 的 `translate`、`scale`、`shear` 按 x、y 顺序各写 4 个，共 8 个。`rotate`、`translatex` 等单属性时间线用 4 个。
- 不写 `curve` 表示线性；`"stepped"` 表示保持到下一键。末键没有后续区间，无需曲线。

归一化控制点 `(a, b)` 转换到区间 `(t0, v0)` → `(t1, v1)`：

```text
控制点时间 = t0 + a × (t1 − t0)
控制点数值 = v0 + b × (v1 − v0)
```

例如 y 从 0.4 秒的 10 变到 1.0 秒的 30，x 保持 0，使用归一化控制点 `(0.25, 0)`、`(0.75, 1)`：

```json
[
  {
    "time": 0.4,
    "x": 0,
    "y": 10,
    "curve": [0.55, 0, 0.85, 0, 0.55, 10, 0.85, 30]
  },
  { "time": 1.0, "x": 0, "y": 30 }
]
```

该对称示例在 0.7 秒应得到 y 约为 20。常值通道也需要完整控制点；少写属性的控制点可能产生 NaN，并传播到整个骨架。

验证转换层时至少覆盖非零起始时间、负值、常值通道、多属性曲线、循环边界与有限数值；用目标运行库实际采样，而不只检查 JSON 能否解析。骨骼列表保持父级先于子级，名称、附件路径和皮肤映射完整。

密集烘焙采样后再线性插值，也必须检查采样点之间的运行时结果；改用稀疏贝塞尔关键帧时，应重新验证中间轨迹和边界。采样率提高不能补救错误的姿势与节奏。

## 10. 验收：画面、连续性与接入分别记录

### 10.1 对照与观看方式

制作同时间、同尺度、同地平线的参考图与 Spine 渲染并排对照，提供透明叠图、轮廓模式和当前部件变体标记。相机固定，不逐帧自动调整角色位置或大小。

覆盖全部动作和动作间衔接，以原速、0.25 倍速、逐帧及目标实际显示尺寸检查。每次附件切换保存前一帧、切换帧、后一帧，并检查它们之间的插值；可用 120 FPS 采样辅助发现短时故障，再对可疑时刻加密。

画面逐项检查：身份与数量、姿势与意图、持物手可追踪性、胸背朝向、头身比例、关节接缝、道具刚性、鞋底和手掌接地、衣物穿插、换图轮廓及内部线条、动作节奏与重量感。

### 10.2 尺寸、轨迹与接触检查

在运行时实际变形后的网格上，按纹理 alpha 对面积与重心加权，排除透明留白；比较切换点两侧极短时间间隔，减少正常运动造成的差异。部件独立渲染面积与被其他部件遮挡后的屏幕可见面积应区分，避免把遮挡变化误判为体积跳变。

记录各姿势的尺寸校准、关节锚点和绑定依据。头部与握持手分别设置检查门槛；躯干、腿部的投影面积变化结合透视、剪影和参考图复核。不同角度不能强行追求完全相等的面积，更不能用全角色缩放掩盖局部尺寸错误。

阈值应根据角色尺度、显示尺寸、采样间隔和已知故障确定并保存。可用相对面积变化、像素或相对身高位移、单位时间速度等指标；不能直接套用其他角色的固定单位阈值，也不能为让测试通过而放宽门槛。

检查等时间轨迹点、速度谷、方向突折、接触段滑动和循环速度衔接。速度可用位置差分估计，报告中写明采样间隔。位置、面积和重心都连续，仍可能因轮廓或衣纹突变而视觉跳动；数值只定位异常，不给自然程度打分。

### 10.3 结构与运行检查

| 层面 | 必查项目 |
| --- | --- |
| 结构 | 匹配版本运行库可加载，附件与纹理存在，坐标有限，权重和网格有效，源图路径可用。 |
| 播放 | 首帧状态完整，循环与末帧保持正确，动作衔接及混合稳定，事件时间和次数正确。 |
| 变形 | 无异常尖峰、拉长、折叠、反转或脱节；网格反折指标排除纯透明区域的干扰，并结合渲染判断。 |
| 引擎接入 | 加载器、资源路径、动画名与触发映射、显示尺寸、选择边界和事件接线正确。 |
| 实际流程 | 单动作、完整动作链、正常交互及允许的打断/恢复路径都经过目标引擎验证。 |

浏览器预览、编辑器导入、原生引擎渲染和实际交互各自记录通过、失败或未测及原因。可加载或可进入场景，不等于动作视觉合格。

保留固定相机、原速播放的前后对比录像，检查非黑屏、画面变化和实际采集帧率，区分录制掉帧与动画停顿。慢放和数据用于定位，原速观看用于判断动作是否成立。

失败记录应包含版本、动作、时间、槽位、旧新附件、数值、截图和原因。修复后重跑原始失败用例，并保留相同时刻的修正画面；视觉与接入验证完成前，不将版本标为最终完成。

## 11. 修正顺序与记录模板

按“参考姿势与身份 → 重心和主节奏 → 接触与轨迹 → 绑定和体积 → 换图轮廓 → 跟随细节 → 导出接入”处理问题，避免在错误动作上反复微调。

| 现象 | 优先检查 |
| --- | --- |
| 每经过一张姿势就停顿 | 是否对所有区间统一缓入缓出，是否误把经过姿势当停顿。 |
| 端点正确，中间被拉扯 | 绑定姿势是否匹配、权重是否跨部位、换图是否过早或过晚。 |
| 手腕移动牵扯衣服或腿 | 全身网格的影响范围及控制点交叉，改为必要的局部权重。 |
| 换图时头手突然变大或跳位 | alpha 体积、锚点、裁切偏移、颈腕连接及运行时变形。 |
| 部件大小稳定却仍闪跳 | 外轮廓、内部线条、层级及全身同步换图。 |
| 接缝露洞、手脚滑地 | 补画余量、相邻网格接口、世界接触点与约束切换。 |
| 循环边界跳变或遗留部件 | 位置和速度衔接、偏移后的首末键、入口复位与播放混合。 |
| 导入后静止、消失或缺图 | 版本、旋转字段、曲线控制点数量、有限数值、源图和图集路径。 |

动作任务模板：

```text
动作名称与输入版本：
输入骨架、素材及哈希：
动作意图与开始/结束姿势：
阶段、预计时长、停顿/经过/接触/反向姿势：
重心、支撑点、握持与刚体约束：
需补的透视图及允许修改的骨骼、槽、附件：
循环、保持、事件、衔接与打断规则：
输出内容、目标运行库及验收方式：
```

每轮修正以明确基线保存“原值 → 增量 → 最终值”，记录动作、时间范围、姿势、槽/附件、坐标空间、输入哈希、原因和前后证据。零改动也可记录为已检查；只有同一坐标空间中的加法偏移才能直接累加，避免重复应用修正。

加权网格修改须记录绑定姿势、顶点与权重变化，不能伪装成 Region 附件的 `x/y` 偏移。换皮、补画与动作修改分别留档，确保能定位差异并回退。

## 12. 导出与交付清单

编辑器与运行库的主、次版本应匹配，并记录具体补丁版本。任何格式转换、重新打包和像素修改后，都应重新运行对应检查。

- **工程与输入：** 实际保存的 `.spine` 工程、部件源图、原始参考图、生成提示词和参数、锚点、绑定姿势及替换关系。仅生成 JSON 时标为“可导入 JSON”，不能改扩展名冒充编辑器工程或二进制数据。
- **运行资源：** 目标加载器支持的 JSON 或二进制骨架数据、atlas、全部纹理页、动画与事件映射。核对附件路径、原图尺寸、裁切偏移、图集旋转、UV、边距及透明混合设置，检查黑边、白边和邻图串色。
- **制作记录：** 关键姿势时间表、素材诊断与哈希、修正记录、工具和依赖版本、重建脚本及调用顺序。完整解包后，源图和相对路径仍应可用。
- **验证材料：** 参考对照页、切换邻帧、轨迹与连续性报告、失败回归记录、原速录像，以及编辑器、运行库和目标引擎各自的验证结论。
- **预览与边界：** 如需离线预览，交付本地固定版本运行库并验证断网加载；说明尚未验证的环节和已知问题，排除无关研究素材与未获准交付的资源。

交付前按完整流程播放一次，确认进入、循环、释放、受击、结束或恢复等路径符合任务定义，并保证收件人能根据包内文件重建和复查结果。
