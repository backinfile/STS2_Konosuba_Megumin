# 体系驱动卡池设计流程

本文用于规范“由用户提出体系，再逐步生成完整职业卡池”的工作流程。目标不是一次性列出 88 张牌，而是先把每个体系的核心玩法打磨清楚，再通过多轮对抗、整合和数量校准，产出可评审的完整卡池初版。

本流程应与以下文档配合使用：

- `docs/职业卡池设计要求_按五职业规律.md`
- `docs/体系分析流程.md`
- `docs/卡牌分析流程.md`

## 基本原则

卡池设计从体系开始，而不是从单卡开始。每个体系都应先回答“玩家为什么围绕这个核心构筑”，再进入卡牌设计。

正式推进前必须先建立职业卡池设计追踪文档。追踪文档是本流程的单一事实来源，用来记录玩家要求、硬约束、当前阶段、待裁决问题、体系状态和卡位变化。后续所有阶段的结论都应回写到追踪文档，而不是只保留在对话中。

除准备追踪文档外，主体设计分为五层：

1. 探索用户给出的体系输入。
2. 对抗并确定体系核心玩法配合。
3. 对抗并产出机制突破牌。
4. 综合生成该体系的完整卡牌初版。
5. 汇总所有体系，调整卡位分配，补齐体系外牌。

“子 agent 对抗”不是为了制造更多方案，而是为了暴露盲点。每轮对抗必须产出可合并的结论：保留什么、删除什么、需要用户裁决什么。

## 子 agent 角色

每轮对抗至少包含以下角色。实际执行时可以由多个子 agent 分别承担，也可以由同一助手按角色顺序模拟。

| 角色 | 职责 | 主要输出 |
| --- | --- | --- |
| 体系设计者 | 基于用户输入提出核心玩法、触发、收益和卡位设想。 | 正向方案。 |
| 规则审稿者 | 检查是否符合体系判定标准，防止伪体系。 | 反例、缺口、降级建议。 |
| 原版对照者 | 对照五职业规律和原版参照体系。 | 原版参照、稀有度和卡位建议。 |
| 平衡审稿者 | 检查节奏、端口、费用、稀有度和过强组合。 | 风险、限制、替代方案。 |
| 卡牌游戏婆罗门 | 以精通多种卡牌游戏的玩家视角，检查机制审美、体系深度、文本风格、突破牌吸引力、职业端口和跨体系连接。 | 婆罗门检查结论、退回修改项、复核状态。 |
| 整合者 | 合并冲突意见，形成当前阶段定稿。 | 决议表和下一步问题。 |

每轮对抗都要避免只给抽象评价。审稿意见必须落到具体字段：触发、收益、端口、卡位、稀有度、费用、风险或需要删除的设计。

卡牌游戏婆罗门是额外检查器，不替代其他角色。任何阶段如果没有通过婆罗门检查，必须选择以下处理方式之一：

- 退回体系设计者、规则审稿者、原版对照者或平衡审稿者修改，再由婆罗门复核。
- 标记为待用户裁决，并把问题写入追踪文档。
- 如果只是风格或卡牌描述问题，先降级为文本待精修，不阻塞结构设计；但最终交付前必须复核通过。

### 卡牌游戏婆罗门检查标准

| 编号 | 检查项 | 不通过时的处理 |
| --- | --- | --- |
| P-01 | 一个基础机制需要有多种触发来源，不能只靠打出卡牌主动触发；优先关联游戏本体中已有要素，例如失去生命值、消耗、无色牌衍生等。 | 退回机制设计，补充被动触发、敌我状态触发、区域变化触发或本体要素关联。 |
| P-02 | 一个体系内部如果存在多种利用机制的方式，应额外加分；同一体系的不同局可以走不同玩法路线。 | 退回体系设计，增加至少两条可抓牌成型的玩法分支，或说明为什么该体系必须保持单线。 |
| P-03 | 卡牌描述必须贴近游戏本体风格，短、清楚、动作明确；避免大量说明文字和小作文。 | 退回文本设计，压缩为原版式句型；复杂规则转移到关键词定义或设计备注。 |
| P-04 | 要有足够的突破限制牌；突破牌必须效果唯一、易理解、够炫酷，让玩家第一眼想尝试。 | 退回突破牌设计，删除纯数值强牌，补足真正改变构筑边界的牌。 |
| P-05 | 一个职业至少有一个提供大量运转的体系，至少有一个能提供巨量输出的体系，且全职业至少有 3 张非稀有的有抽牌效果的卡牌。 | 退回职业级卡位预算，补运转、补输出或下放抽牌效果到普通/罕见。 |
| P-06 | 如果已有一个很复杂的体系，其他体系要尽量精简，为复杂体系让渡玩家理解力，降低上手难度。 | 退回复杂度预算，压缩其他体系的关键词、持续监听和例外规则。 |
| P-07 | 不同体系之间必须提供跨体系牌，且连接方式不能只是关键词拼接。 | 退回连接牌设计，明确连接牌同时解决两个体系的真实需求。 |
| P-08 | 同一角色的多个体系之间，要么是同一机制的正交维度，例如冰充能球、闪电充能球、黑暗充能球；要么是完全不同的维度，例如消耗-卡牌移动效果、格挡-攻防资源、生命值损失-跨战斗资源。 | 退回职业级体系规划，合并换皮体系，或把相邻体系改成正交维度 / 完全不同维度。 |
| P-09 | 卡牌之间要有关系美感：0/1/2 费牌共享一个机制效果但基础效果不同是美的；两张牌卡面描述一模一样不美；两张牌卡面效果完全相反减分；两张牌只有一点区别但几乎相同或相反减分；两张牌有两点区别外一模一样属于正常设计；金卡不能只是普通或罕见牌的上位替代，除非它是突破限制牌。 | 退回卡牌组设计，合并重复牌，增加第二个差异点，改成共同机制下的不同基础效果，或把金卡改成真正突破限制牌。 |

### 卡牌游戏婆罗门 agent 执行协议

婆罗门不是第六个方案生成器，而是体验审计 agent。它默认不新增大批卡牌，只判断当前设计是否值得继续投入，并把问题退回给最适合修正的角色。

#### 输入包

每次调用婆罗门前，至少提供以下内容；缺项必须在结论中标为“信息不足”，不能假装通过。

- 当前阶段：阶段 1-5 / 阶段 7 / 阶段 9。
- 当前审查对象：单体系、突破牌组、单体系卡表、全职业卡位预算或完整卡池。
- 玩家硬约束：必须保留、禁止、待确认的要求。
- 机制摘要：扳机、来源、收益、限制、例外。
- 卡表或候选表：编号、费用、稀有度、类型、效果草案、卡位角色。
- 已知风险：无限、过量抽牌、过量能量、文本复杂度、记忆负担。
- 追踪文档状态：上一轮退回项、待裁决问题、已采用修改。

#### 审查顺序

婆罗门按固定顺序审查，避免被某张炫酷单卡带偏。

1. 先看职业或体系身份是否清楚。
2. 再看 P-01/P-02：机制有没有多来源、多路线。
3. 再看 P-04/P-05：突破、运转和巨量输出是否足够吸引玩家构筑。
4. 再看 P-06/P-07/P-08：复杂度、跨体系连接和体系维度是否健康。
5. 最后看 P-03/P-09：文本风格和卡牌关系美感。

#### 阶段适用矩阵

不是每个阶段都要强行判定 P-01 到 P-09。暂时无法判定的项目应写“不适用”或“待复核”，并说明下一次复核触发条件。

| 阶段 | 必查项 | 可初筛项 | 暂不强判项 |
| --- | --- | --- | --- |
| 阶段 1：单体系探索 | P-01、P-02、P-06 | P-08 | P-03、P-04、P-05、P-07、P-09 |
| 阶段 2：核心玩法对抗 | P-01、P-02、P-06 | P-07、P-08 | P-03、P-04、P-05、P-09 |
| 阶段 3：突破牌对抗 | P-04 | P-03、P-09 | P-05、P-07、P-08 |
| 阶段 4：单体系卡表初版 | P-03、P-09 | P-01、P-02、P-04、P-06 | P-05、P-07、P-08 |
| 阶段 5：单体系评审 | P-01、P-02、P-03、P-04、P-06、P-09 | P-07、P-08 | P-05 |
| 阶段 7：卡位重分配 | P-05、P-06、P-07、P-08 | P-04、P-09 | P-01、P-02、P-03 |
| 阶段 9：完整卡池评审 | P-01 到 P-09 | 无 | 无 |

#### 判定等级

| 等级 | 含义 | 后续动作 |
| --- | --- | --- |
| 通过 | 当前阶段的信息足够，且没有阻塞后续设计的问题。 | 进入下一阶段，并把通过原因写入追踪文档。 |
| 局部通过 | 本阶段目标成立，但仍有明确缺口等待后续阶段补足。 | 可以继续推进，但必须生成待补项和复核触发条件。 |
| 退回修改 | 存在会污染后续卡池的结构问题。 | 指定退回对象和最小修改目标，修改后再复核。 |
| 待用户裁决 | 问题属于主题偏好、复杂度接受度或硬约束冲突。 | 写入待裁决问题，不用 agent 自行拍板。 |
| 信息不足 | 输入包缺关键内容，无法判断。 | 补齐缺项后再审查。 |

#### 输出格式

```markdown
### 卡牌游戏婆罗门审查：{阶段 / 对象}

- 判定：通过 / 局部通过 / 退回修改 / 待用户裁决 / 信息不足
- 审查范围：
- 核心结论：
- 最强设计点：
- 最大风险：
- 必须退回项：
- 可延后精修项：
- 需要用户裁决：
- 复核触发条件：

| 检查项 | 结论 | 证据 | 退回对象 | 处理 |
| --- | --- | --- | --- | --- |
| P-01 触发来源 | 通过 / 局部通过 / 退回 / 不适用 |  | 体系设计者 / 规则审稿者 / 平衡审稿者 / 用户 / 无 |  |
```

#### 退回路由

| 问题类型 | 优先退回对象 | 最小修改目标 |
| --- | --- | --- |
| 机制只有单一主动触发 | 体系设计者 | 补 1-2 个非主动触发来源，或降级为小体系 / 效果组。 |
| 来源很多但没有抓牌理由 | 体系设计者 | 补收益牌、次数兑现牌或高质量目标奖励。 |
| 规则边界含糊 | 规则审稿者 | 写清时点、区域、次数限制、例外和不能做的事。 |
| 纯数值突破牌 | 原版对照者 / 体系设计者 | 改成改变资源流失、结算次数、持续来源或构筑边界。 |
| 循环、免费、爆发过强 | 平衡审稿者 | 增加费用、消耗、每回合限制、稀有度上调或目标限制。 |
| 文本像说明书 | 规则审稿者 / 整合者 | 将规则移入关键词定义，把卡面压回动作短句。 |
| 卡牌关系不美 | 体系设计者 / 原版对照者 | 合并重复牌，或让同机制牌承担不同基础任务。 |
| 体系之间换皮 | 整合者 / 用户 | 合并体系，或改成正交维度 / 完全不同维度。 |

#### 常见红线

- 不能因为主题好看就放过单来源机制。
- 不能用“后续数值调整”掩盖结构性无限。
- 不能把所有稀有牌都写成低稀有牌的加强版。
- 不能把复杂规则塞进普通牌，再用备注解释。
- 不能为了满足跨体系连接，把两个关键词生硬贴在一张牌上。
- 不能只说“有趣 / 无聊 / 强 / 弱”，必须指出是哪张牌、哪个字段导致结论。

## 阶段 -1：建立职业卡池设计追踪文档

```text
docs/{角色名}职业卡池设计记录.md
```

如果角色名尚未确定，可以先使用临时名称，例如 `docs/未命名职业卡池设计记录.md`，确定后再重命名。

### 目标

- 记录玩家最初提出的需求、偏好、禁忌和硬约束。
- 追踪流程当前推进到哪一阶段，哪些体系已完成、哪些还在等待裁决。
- 保存每轮子 agent 对抗后的整合结论，避免只在对话里丢失。
- 维护卡位预算、体系卡牌数、稀有度数量和待补洞清单。
- 记录用户裁决和重要变更，方便后续回滚或解释设计来源。

- 用户原始需求。
- 角色主题、玩法幻想或参考角色。

## 阶段 0：建立职业设计上下文

在处理单个体系前，先建立职业级约束。

### 输入

- 角色主题或幻想。
- 用户初步提出的体系列表。
- 已知关键词、资源、衍生牌或特殊规则。
- 是否服务多人模式。
- 是否必须继承旧 Mod 的某些机制。

### 输出

```markdown
## 职业设计上下文

- 角色身份：
- 第一资源或第一事件：
- 主要体验目标：
- 预期强项：
- 预期弱项：
- 候选大体系：
- 候选小体系：
- 必须保留机制：
- 禁止或避免机制：
- 复杂度预算：高复杂体系 / 中复杂体系 / 低复杂体系
- 职业运转体系候选：
- 职业巨量输出体系候选：
- 非稀有抽牌牌目标：
- 体系维度关系：同一机制正交维度 / 完全不同维度 / 待调整
```

### 通过标准

- 至少有一个职业第一资源或第一事件。
- 每个候选体系都有一句话说明，不只是功能标签。
- 可以暂时不确定体系数量，但必须知道哪些内容需要继续追问。
- 初步指出哪个体系承担大量运转，哪个体系承担巨量输出。
- 如果存在高复杂体系，其他体系必须标记为中低复杂度候选，避免全职业理解负担过高。
- 记录全职业至少 3 张非稀有抽牌牌的设计目标。
- 初步判断多个体系之间的维度关系，避免出现多个只在收益或名字上不同的换皮体系。

## 阶段 1：探索用户给出的单个体系

本阶段只处理一个体系。目标是把用户的直觉转成可判定的体系候选。

### 输入

用户对体系的自然语言描述，例如：

- “围绕演出状态叠层。”
- “通过生成衍生牌打连击。”
- “牺牲防御换取下一回合爆发。”

### 追问顺序

一次只问一个关键问题。能从文档和已有上下文判断的，不问用户。

1. 这个体系的核心是什么：关键词、资源、Power、卡牌标签，还是触发事件？
2. 什么行为算触发扳机？
3. 扳机的主要收益是什么？
4. 这个体系天然覆盖输出、防御、运转中的哪些端口？
5. 玩家第一次看到哪类低稀有牌，会理解这是一个构筑方向？
6. 这个体系缺哪个端口，是否需要其他体系或体系外牌补洞？
7. 这个体系的触发来源是否不止一种，是否存在不依赖主动打出卡牌的触发？
8. 这个体系内部是否可能有两种以上玩法路线？

### 输出

```markdown
## 体系候选：{名称}

- 核心：
- 判定倾向：大体系 / 小体系 / 效果组 / 待定
- 扳机定义：
- 主要来源：
- 主要收益：
- 输出端：
- 防御端：
- 运转端：
- 低稀有入口：
- 主要缺口：
- 与其他体系的潜在连接：
- 触发来源多样性：
- 体系内玩法分支：
- 复杂度等级：高 / 中 / 低
- 婆罗门初检：
- 待裁决问题：
```

### 通过标准

- 不能只用“高伤害”“抽牌”“格挡”“召唤”“生成”描述体系。
- 必须能说清来源和收益至少各一类。
- 至少能判断它更像大体系、小体系还是效果组。
- 基础机制不能只有“打出某类卡牌”这一种触发来源；如果暂时只有一种，必须标为待修改或待用户裁决。
- 至少判断体系是否有多玩法潜力；没有多玩法潜力时，必须解释它为什么适合作为小体系、效果组或低复杂补充体系。

## 阶段 2：体系核心玩法对抗

本阶段通过子 agent 对抗确定体系的核心玩法配合。目标不是生成很多卡，而是确定这套体系到底靠什么成立。

### 对抗任务

| 角色 | 要回答的问题 |
| --- | --- |
| 体系设计者 | 这个体系最自然的玩法闭环是什么？ |
| 规则审稿者 | 它是否有共同核心，还是只是效果相似？ |
| 原版对照者 | 原版五职业里最接近的体系是什么，应该借鉴哪类卡位？ |
| 平衡审稿者 | 这套玩法的主要滥用点、卡手点和端口缺口是什么？ |
| 卡牌游戏婆罗门 | 机制是否有多触发来源、是否关联本体要素、体系内是否有多玩法路线、复杂度是否值得？ |
| 整合者 | 最终保留哪条玩法闭环，删掉哪些伪方向？ |

### 输出

```markdown
## 体系核心玩法定稿：{名称}

- 判定：大体系 / 小体系 / 效果组
- 核心玩法闭环：
- 主要构筑动机：
- 来源牌应承担：
- 收益牌应承担：
- 多触发来源：
- 体系内玩法路线：
- 需要的端口转换：
- 不应纳入本体系的伪方向：
- 原版参照：
- 复杂度等级：
- 婆罗门结论：
- 主要风险：
```

### 通过标准

- 至少有一条“来源 -> 收益 -> 继续抓牌理由”的闭环。
- 明确哪些设计不属于本体系，防止后续卡位膨胀。
- 如果判定为效果组，应停止为它生成完整体系牌，只保留为功能标签或体系外素材。
- 大体系必须有至少两类触发来源，其中至少一类不是“主动打出某类卡牌”。
- 大体系优先保留两条以上可成型玩法路线；如果只有一条路线，需要降复杂度或缩小卡位。

## 阶段 3：机制突破牌对抗

本阶段为该体系寻找 0-3 张真正的突破限制牌。突破牌不是强数值牌，而是改变体系边界。

### 候选突破方向

优先从以下方向中选择：

| 突破方向 | 含义 |
| --- | --- |
| 资源不再流失 | 绕开回合结束、卡手、一次性收益等限制。 |
| 来源变成收益 | 做机制这件事本身产生抽牌、格挡、力量、能量等回报。 |
| 容量或倍率扩大 | 扩大资源容量、收益倍率、结算次数。 |
| 批量触发或额外打出 | 突破一回合费用、出牌次数或结算次数限制。 |
| 防御转输出 | 把格挡、承伤、召唤物生命等转成伤害。 |
| 输出转运转 | 把造成伤害、击杀或状态层数转成抽牌、能量、生成。 |
| 持续资源生成 | 把一次性来源变成每回合来源。 |

### 对抗任务

| 角色 | 要回答的问题 |
| --- | --- |
| 体系设计者 | 提出 3-6 张突破牌方向。 |
| 规则审稿者 | 删除只是大数字、泛用强牌或不改变构筑的候选。 |
| 原版对照者 | 为每个保留候选找原版参照或突破模式。 |
| 平衡审稿者 | 给出稀有度、费用、限制和风险。 |
| 卡牌游戏婆罗门 | 哪些突破牌效果唯一、易理解、够炫酷，能让玩家第一眼想试？哪些只是无聊强牌？ |
| 整合者 | 定下 1-3 张突破牌的设计目标。 |

### 输出

```markdown
## 机制突破牌定稿：{体系名称}

| 编号 | 突破方向 | 突破的限制 | 补足端口 | 推荐稀有度 | 设计目标 | 炫酷点 | 风险与限制 | 婆罗门复核 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| B-01 |  |  |  |  |  |  |  |  |
```

### 通过标准

- 大体系通常保留 1-3 张突破牌。
- 小体系通常保留 0-2 张突破牌。
- 每张突破牌都必须说明它突破了什么限制。
- 如果说不清突破点，应降级为核心收益牌、终结牌或体系外强牌。
- 突破牌必须效果唯一且易理解；如果只能靠长说明解释，应退回重做。
- 职业第一体系或高复杂体系应优先配置足够突破牌，避免只有数值奖励没有构筑惊喜。

## 阶段 4：生成单个体系的完整卡牌初版

本阶段才开始生成具体卡牌。目标是产出该体系的一组完整卡位，而不是最终数值定稿。

### 大体系默认卡位

大体系通常 12-20 张。职业第一体系可以更多。

| 卡位角色 | 推荐数量 | 推荐稀有层 | 设计任务 |
| --- | ---: | --- | --- |
| 低稀有入口 | 1-3 | 普通 | 单独抓不亏，并提示继续找配套。 |
| 稳定来源 | 3-6 | 普通/罕见 | 制造体系扳机，同时给基础输出、防御或运转。 |
| 核心收益 | 2-5 | 罕见/稀有 | 把扳机转为伤害、生存、抽牌、能量或长期成长。 |
| 突破限制 | 1-3 | 稀有/远古 | 改变体系边界或补关键端口。 |
| 中坚与连接 | 2-5 | 罕见/稀有 | 补数量、补端口，或连接其他体系。 |

### 小体系默认卡位

小体系通常 7-11 张。

| 卡位角色 | 推荐数量 | 推荐稀有层 | 设计任务 |
| --- | ---: | --- | --- |
| 副轴入口 | 0-1 | 普通/罕见 | 低成本展示副轴方向。 |
| 触发素材 | 2-4 | 普通/罕见 | 提供副轴素材或触发条件。 |
| 副轴收益 | 1-3 | 罕见/稀有 | 让玩家愿意围绕副轴调整抓牌。 |
| 上限牌 | 0-2 | 稀有 | 提供爆发或长期奖励。 |
| 补洞牌 | 1-3 | 罕见/稀有 | 补输出、防御、运转或连接主体系。 |

### 卡牌初版字段

每张牌至少记录以下字段：

```markdown
| 编号 | 名称 | 稀有度 | 类型 | 费用 | 卡位角色 | 扳机角色 | 端口 | 效果草案 | 玩法路线 | 相似牌关系 | 升级方向 | 独立性 | 风险 | 文本复杂度 | 美感检查 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
```

### 生成顺序

1. 先生成普通入口和稳定来源。
2. 再生成罕见收益牌和连接牌。
3. 再放入阶段 3 定稿的突破牌。
4. 最后补中坚牌和端口缺口。

### 通过标准

- 普通层能看懂体系入口。
- 触发牌和收益牌成对存在。
- 至少记录输出、防御、运转端口覆盖情况。
- 每张牌都有卡位角色，不允许只有效果没有定位。
- 卡牌描述先保持草案，不急于精修数值。
- 每张牌的效果草案都应能压缩成接近原版风格的短句；需要小作文才能解释的牌必须标为高文本复杂度并等待精修或重做。
- 同一大体系的卡牌应支持至少两条玩法路线，不能全部只服务同一种收益。
- 允许多张不同费用牌共享同一个机制效果，但基础效果应不同，例如一张造成伤害、一张获得格挡、一张提供运转。
- 避免卡面描述一模一样、完全相反、或只有一点区别的换皮牌。
- 稀有牌不能只是普通或罕见牌的数值上位替代；除非它同时承担突破限制牌定位。

## 阶段 5：单体系对抗评审

体系初版生成后，必须再经过一轮对抗评审。

### 评审问题

| 维度 | 问题 |
| --- | --- |
| 体系完整性 | 来源、收益、突破、补洞是否齐全？ |
| 入口清晰度 | 普通/罕见层是否能让玩家看懂构筑方向？ |
| 端口覆盖 | 输出、防御、运转是否至少覆盖两个？缺口是否有解释？ |
| 稀有度结构 | 核心奖励是否过度集中在稀有牌？ |
| 费用结构 | 是否有足够 1 费牌？0 费、高费和 X 费是否服务节奏？ |
| 过强组合 | 是否存在无需铺垫的无限、过量免费、过量抽牌或无脑复制？ |
| 伪体系膨胀 | 是否混入只属于体系外牌或其他体系的功能？ |
| 触发来源 | 基础机制是否有多种触发来源，且不只靠主动打出卡牌？ |
| 玩法分支 | 同一体系内是否存在多种可成型利用方式？ |
| 文本审美 | 是否有大量说明文字、小作文或不像原版的描述？ |
| 突破吸引力 | 突破牌是否效果唯一、易理解、让人想试？ |
| 复杂度预算 | 如果本体系很复杂，是否会挤占其他体系的理解空间？ |
| 跨体系潜力 | 是否有真实连接其他体系的牌位或机制接口？ |
| 卡牌关系美感 | 是否存在描述一模一样、完全镜像、只有一点差异的换皮牌，或稀有牌只是低稀有牌上位替代？ |

### 输出

```markdown
## 单体系评审结论：{体系名称}

- 保留：
- 删除：
- 合并：
- 降级为体系外：
- 需要连接到其他体系：
- 需要用户裁决：
- 婆罗门退回修改项：
- 婆罗门复核状态：
- 卡牌关系美感：
- 当前卡牌数：
- 建议目标卡牌数：
```

## 阶段 6：重复处理所有体系

对用户提出的每个体系重复阶段 1-5。

每完成一个体系，都要先更新追踪文档中的体系进度索引、待裁决问题、阶段结论日志和卡位与数量追踪，再进入下一个体系。

处理顺序建议：

1. 职业第一体系。
2. 与第一体系连接最紧的第二体系。
3. 其他大体系。
4. 小体系和副轴。
5. 只可能是功能标签的候选方向。

每完成一个体系，都要更新职业级体系索引：

```markdown
## 职业体系索引

| 体系 | 判定 | 当前卡牌数 | 目标卡牌数 | 输出 | 防御 | 运转 | 体系维度 | 连接对象 | 风险 |
| --- | --- | ---: | ---: | --- | --- | --- | --- | --- | --- |
```

## 阶段 7：全卡池数量对抗与卡位重分配

所有体系都有初版后，进入职业级数量协调。

### 默认总量

| 分组 | 默认数量 |
| --- | ---: |
| 基础牌 | 4 |
| 普通牌 | 20 |
| 罕见牌 | 36 |
| 稀有牌 | 26 |
| 远古牌 | 2 |
| 合计 | 88 |

### 默认功能分配

| 分组 | 推荐范围 | 默认落点 |
| --- | ---: | ---: |
| 大体系奖励牌合计 | 36-52 | 44 |
| 小体系奖励牌合计 | 14-24 | 18 |
| 跨体系连接牌 | 3-5 | 4 |
| 体系外奖励牌 | 13-19 | 16 |
| 远古牌 | 2 | 2 |

### 对抗任务

| 角色 | 要回答的问题 |
| --- | --- |
| 体系设计者 | 哪些体系最能代表职业身份，应该多拿卡位？ |
| 规则审稿者 | 哪些体系其实是小体系或效果组，应该缩减？ |
| 原版对照者 | 当前数量是否接近五职业结构规律？ |
| 平衡审稿者 | 哪些体系过密、过稀或缺低稀有入口？ |
| 卡牌游戏婆罗门 | 是否至少有一个大量运转体系、一个巨量输出体系、3 张非稀有抽牌牌；复杂体系是否让渡了其他体系复杂度；跨体系牌是否足够；多个体系之间是否是正交维度或完全不同维度？ |
| 整合者 | 给出最终卡位预算表。 |

### 输出

```markdown
## 卡位预算表

| 分组 | 目标卡牌数 | 普通 | 罕见 | 稀有 | 远古 | 运转 | 巨量输出 | 非稀有抽牌 | 复杂度 | 体系维度关系 | 说明 |
| --- | ---: | ---: | ---: | ---: | ---: | --- | --- | ---: | --- | --- | --- |
| 起始牌 | 4 |  |  |  |  |  |  |  |  |  |  |
| 体系 A |  |  |  |  |  | 是 / 否 | 是 / 否 |  | 高 / 中 / 低 | 同一机制正交维度 / 完全不同维度 |  |
| 体系 B |  |  |  |  |  | 是 / 否 | 是 / 否 |  | 高 / 中 / 低 | 同一机制正交维度 / 完全不同维度 |  |
| 连接牌 |  |  |  |  |  |  |  |  |  |  |  |
| 体系外奖励牌 |  |  |  |  |  |  |  |  |  |  |  |
| 合计 | 88 | 20 | 36 | 26 | 2 |  |  | 至少 3 |  |  |  |
```

### 通过标准

- 总数接近或等于 88。
- 普通牌为 20，且普通牌无能力牌。
- 罕见牌为 36，承担成型与连接。
- 稀有牌为 26，承担突破和强规则。
- 远古牌为 2。
- 体系外牌保留 15-21 张左右，不为了归类而消灭补洞牌。
- 至少一个体系明确承担大量运转，至少一个体系明确承担巨量输出。
- 全职业至少有 3 张非稀有的有抽牌效果的卡牌。
- 如果存在高复杂体系，其他体系的复杂度和文本长度必须明显收敛。
- 跨体系连接牌必须保留足够卡位，不能在数量协调中被全部挤掉。
- 多个体系之间必须明确属于同一机制的正交维度，或属于完全不同的设计维度；不能只是同一玩法换不同收益或名字。

## 阶段 8：生成体系外牌补齐卡池

体系外牌在所有体系卡位确定后再生成。它们不是废牌，而是让职业能稳定进入战斗的补洞层。

### 体系外牌功能池

| 功能 | 推荐数量 | 推荐稀有层 |
| --- | ---: | --- |
| 基础纯数值起始牌 | 2 | 基础 |
| 早期单体输出 | 1-3 | 普通 |
| 早期 AoE | 1-2 | 普通/罕见 |
| 泛用防御 | 2-4 | 普通/罕见/稀有 |
| 泛用运转 | 2-4 | 普通/罕见/稀有 |
| 费用工具 | 1-3 | 罕见/稀有 |
| 独立终结 | 1-3 | 罕见/稀有 |
| 长期成长或局外经济 | 1-3 | 稀有/远古 |
| 特殊规则或多人支援 | 0-2 | 罕见/稀有 |

### 通过标准

- 每张体系外牌都能说明为什么不算体系。
- 普通体系外牌优先解决早期输出、防御和 AoE。
- 罕见体系外牌优先放抽牌、回收、减费、保留和中等爆发。
- 稀有/远古体系外牌可以独特，但不抢主体系身份。
- 体系外牌可以补足非稀有抽牌数量，但不能假装成主体系牌。
- 如果主体系过复杂，体系外牌应优先承担简单、直观、低文本负担的战斗功能。

## 阶段 9：完整卡池初版评审

完整卡池初版完成后，按职业级口径评审。

### 结构检查

- 总数是否为 87-88。
- 稀有度是否为基础 4、普通 20、罕见 36、稀有 26、远古 2。
- 普通牌是否没有能力牌。
- 类型分布是否接近职业节奏，而不是机械平均。
- 1 费牌是否接近全卡池一半。
- 0 费、高费、X 费是否都有职业节奏理由。
- 是否至少有 3 张非稀有抽牌牌。

### 体系检查

- 每个大体系是否有来源、收益、突破和补洞。
- 每个大体系是否至少覆盖两个端口。
- 是否至少有一个大量运转体系。
- 是否至少有一个巨量输出体系。
- 基础机制是否有多种触发来源，且至少一种不是主动打出卡牌。
- 每个小体系是否说明依附对象或副轴价值。
- 连接牌是否真的连接两个体系，而不是关键词拼接。
- 突破限制牌是否真的改变构筑边界。
- 突破限制牌是否效果唯一、易理解、足够吸引人。
- 高复杂体系是否已经获得理解力预算，其他体系是否足够精简。
- 大体系内部是否有多种可成型玩法路线。
- 多个体系之间是否是同一机制的正交维度，或完全不同的设计维度。
- 是否保留了足够体系外牌。

### 卡牌关系美感检查

- 是否有 0/1/2 费牌共享一个机制效果，但基础效果分别承担伤害、格挡、运转等不同任务。
- 是否有两张牌卡面描述一模一样。
- 是否有两张牌卡面效果完全相反。
- 是否有两张牌除了一点区别外几乎完全相同或相反。
- 是否有两张牌有两点区别外一模一样；这类通常可以保留。
- 是否有金卡只是普通或罕见牌的上位替代；若有，它是否明确是突破限制牌。

### 文本检查

- 卡牌描述是否使用原版常见句式。
- 普通牌是否保持短句和低复杂度。
- 罕见以上是否才承担复杂条件和持续监听。
- 每张牌是否能拆出对象、动作、数值、时点、区域、限制。
- 是否存在大量说明文字、小作文或明显不像本体卡牌描述的文本。
- 描述评分是否达到 16 分以上。

## 推荐执行节奏

如果设计一个完整职业，推荐按下面节奏推进：

1. 建立或打开职业卡池设计追踪文档，记录玩家要求、当前阶段和待裁决问题。
2. 一轮建立职业上下文，并回写追踪文档。
3. 每个体系单独跑阶段 1-5，每阶段结束都回写体系进度和结论日志。
4. 所有体系完成后，跑阶段 7 的卡位重分配，并更新卡位与数量追踪。
5. 生成体系外牌。
6. 做完整卡池评审，并完成卡牌游戏婆罗门终审。
7. 再进入数值微调和卡牌文本精修。

不要在第一个体系还没定型时急着填满 88 张。越早填满卡池，越容易把“体系缺口”误补成大量无法互相支撑的单卡。
