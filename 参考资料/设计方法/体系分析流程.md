# 体系分析流程

本文用于约束卡牌研究中的“体系”判定，避免把只是效果相似的一组牌误判为体系。

## 基本定义

一个体系不是“效果相似牌的集合”，而是围绕同一个核心机制展开的一系列卡牌。

这个核心通常来自以下几类：

| 核心类型 | 说明 | 例子 |
| --- | --- | --- |
| 关键词 | 游戏规则层面的明确关键词或状态 | 易伤、消耗、虚无、奇巧 |
| 资源 | 可积累、可花费、可检查的数值或区域资源 | 格挡、星、灾厄、消耗牌堆数量 |
| Power | 能力牌提供的持续规则 | 每当消耗时抽牌、格挡不消失 |
| 卡牌标签 | 牌名、牌种、派生牌、角色专属标签等 | 打击、小刀、灵魂、攻击牌 |
| 明确触发条件 | 多张牌共同围绕同一触发条件运作 | 失去生命时、抽到牌时、打出第三张攻击牌时 |

如果没有这样的共同核心，只是“都是高伤害”“都是抽牌”“都是获得格挡”，通常不算体系。

## 不能作为体系核心的伪核心

有些共同点看起来像“核心”，但只能作为功能标签或端口描述，不能单独拆成体系：

| 伪核心 | 为什么不算体系 | 正确处理 |
| --- | --- | --- |
| 作用对象相同 | 只是效果指向同一类目标，没有形成独立扳机和收益 | 记录到对应端口，例如防御端、输出端 |
| 作用范围相同 | 单体、群体、随机目标等只是结算方式 | 作为效果描述，不单列体系 |
| 功能用途相同 | 抽牌、能量、回血、减费、升级等通常是运转或防御功能 | 归入服务的真实体系，或作为功能标签 |
| 牌面措辞相似 | 文本里都出现同一对象或同一动词，不代表存在构筑核心 | 继续检查是否有触发牌、收益牌和牌间需求 |

例如，“给另一位玩家格挡”“敌人的伤害对盟友减半”都指向盟友保护，但它们没有共同扳机，也没有围绕“盟友承伤”产生收益的牌，因此不应拆成多人承伤体系。它们应归入格挡、防御端或盟友保护功能标签。

## 三个端口

判断一个机制是否形成体系时，优先看它是否覆盖多个端口。

| 端口 | 含义 | 常见表现 |
| --- | --- | --- |
| 输出端 | 机制如何造成伤害或提高伤害 | 直接伤害、额外攻击、增伤、斩杀、反伤 |
| 防御端 | 机制如何减少伤害或提供生存 | 格挡、虚弱、力量降低、覆甲、无实体、回血 |
| 运转端 | 机制如何让牌组持续运作 | 抽牌、能量、减费、检索、复制、生成、回收、保留、消耗触发 |

成熟体系通常至少覆盖其中两个端口，强体系往往三个端口都有。

## 扳机触发与扳机收益

整理体系时，除了输出端、防御端、运转端，还必须统计牌在体系中的扳机角色。

一个体系通常由“扳机”和“收益”组成：

| 角色 | 含义 | 常见表现 |
| --- | --- | --- |
| 扳机触发牌 | 打出后会触发这个体系的扳机，或直接制造该体系正在监听的事件 | 给予易伤、消耗卡牌、失去生命、获得格挡、打出攻击牌 |
| 扳机收益牌 | 当体系扳机触发，或核心资源、状态满足时，获得额外收益 | 每当消耗时抽牌、敌人每有一层易伤就加伤、每当失血时加力量 |
| 触发+收益牌 | 同一张牌既制造扳机，又从同一体系或相邻体系获得收益 | 先给予易伤再按易伤层数结算、消耗牌同时根据消耗数量造成伤害 |
| 跨体系联动牌 | 把一个体系的扳机接到另一个体系的收益上 | 自损并消耗牌、获得格挡并给予易伤、生成攻击牌并免费打出 |

判断体系时，不能只数“相关牌数量”，还要看扳机和收益是否成对存在。

如果只有大量扳机触发牌，但没有足够收益牌，通常只是资源来源或功能标签。  
如果只有收益牌，但本职业内缺少稳定触发牌，这个体系依赖外部条件，通常只能算小体系或不稳定体系。  
如果触发牌和收益牌都存在，并且能覆盖多个端口，才更接近成熟体系。

## 体系内单卡分类与定位

确认某组牌可以作为体系后，还必须继续分析体系中的每一张牌。体系分析不能只写“有哪些牌”，而要说明每张牌在这个体系里承担什么选牌功能、触发职责和端口职责。

每张牌至少要分析四层信息：

| 维度 | 要回答的问题 | 常见取值 |
| --- | --- | --- |
| 体系内分类 | 玩家看到这张牌时，它是在引导进入体系、提供基础燃料、提供核心奖励、突破上限，还是普通补强？ | 机制引导牌、机制基础牌、机制核心牌、突破限制牌、机制中坚牌 |
| 扳机角色 | 它是在制造体系扳机，吃体系收益，还是两者都有？ | 扳机触发、扳机收益、触发+收益、跨体系联动 |
| 端口定位 | 它把体系核心接到哪个战斗需求上？ | 输出端、防御端、运转端，或多个端口 |
| 选牌定位 | 在实际选牌中，这张牌为什么被抓？没有体系配套时是否能抓？ | 入口牌、燃料牌、奖励牌、终结牌、补洞牌、连接牌、上限牌 |

### 体系内分类

同一张牌在同一个体系内只归入一个分类。分类优先级为：

1. 先判断是否为突破限制牌。
2. 再判断是否为机制引导牌、机制基础牌或机制核心牌。
3. 不符合上述条件的体系相关牌，统一归为机制中坚牌。

| 分类 | 判定标准 | 选牌含义 |
| --- | --- | --- |
| 机制引导牌 | 通常为普通或罕见；单独抓取不亏；吃到本体系配套后明显变强；能提示玩家继续寻找本体系牌 | 体系入口牌，负责让玩家看懂构筑方向 |
| 机制基础牌 | 通常为普通或罕见；属于稳定扳机触发牌；单独打出也有基础数值 | 体系燃料牌，负责制造状态、资源或事件 |
| 机制核心牌 | 属于扳机收益牌；没有稳定扳机时表现偏弱；有扳机后收益显著 | 体系奖励牌，决定玩家是否真正进入该体系 |
| 突破限制牌 | 效果唯一，能打破体系原有限制；通常补足输出、防御、运转中的关键缺口 | 体系上限牌，改变构筑边界 |
| 机制中坚牌 | 与体系相关，但不满足引导、基础、核心或突破限制标准 | 体系补强牌，补数量、补端口或提供跨体系连接 |

分类时要避免两种错误：

- 不要把所有强牌都标为突破限制牌。只有改变体系规则、资源利用方式或构筑边界的牌才算突破限制。
- 不要把所有触发牌都标为机制基础牌。如果一张触发牌单独抓取很差、费用过高或只适合特定构筑，它更可能是中坚牌或核心配件。

### 单卡定位写法

逐张牌分析时，建议每张牌至少写清：

| 字段 | 说明 |
| --- | --- |
| 名称 | 卡牌名称 |
| 体系内分类 | 机制引导牌、机制基础牌、机制核心牌、突破限制牌、机制中坚牌 |
| 扳机角色 | 扳机触发、扳机收益、触发+收益、跨体系联动 |
| 端口 | 输出、防御、运转 |
| 定位 | 用一句话说明这张牌在该体系中解决什么问题 |
| 独立性 | 没有体系配套时是否仍然可抓 |
| 依赖或风险 | 需要什么条件才强，或者容易出现什么问题 |

例如：

| 牌 | 体系内分类 | 扳机角色 | 端口 | 定位 |
| --- | --- | --- | --- | --- |
| 给予易伤并造成伤害的普通攻击 | 机制基础牌 | 扳机触发 | 输出 | 提供低稀有度易伤来源，同时不牺牲早期输出 |
| 每当给予易伤时抽牌的能力 | 突破限制牌 | 扳机收益 | 运转 | 把易伤从伤害状态变成持续抽牌扳机 |
| 根据消耗牌堆数量增伤的攻击 | 机制核心牌 | 扳机收益 | 输出 | 奖励玩家持续消耗卡牌，是消耗体系的输出回报 |

跨体系牌需要分别写它在每个体系中的定位。同一张牌在不同体系中可以有不同分类。例如，一张“失去生命、消耗一张牌并获得力量”的牌，在自损体系中可能是机制基础牌，在消耗体系中可能是机制基础牌，在力量轴中可能只是中坚连接牌。

## 跨体系联动牌

跨体系联动牌需要单独标记，因为它们常常会误导体系划分。

这类牌要按具体体系分别判断：如果打出后会触发某体系的扳机，就记为该体系的扳机触发牌；如果是在某体系扳机触发时获得收益，就记为该体系的扳机收益牌。只有当它同时触发并从该核心获得额外收益时，才标为“触发+收益”。

例如：

| 牌的行为 | 在体系整理中的含义 |
| --- | --- |
| 失去生命并获得能量 | 对自损体系是扳机触发；获得能量只是运转端效果 |
| 消耗一张牌并抽牌 | 对消耗体系是扳机触发；抽牌只是运转端效果 |
| 获得格挡并给予易伤 | 同时触发格挡核心和易伤核心，但不一定是收益牌 |
| 每当消耗牌时获得格挡 | 对消耗体系是扳机收益；对格挡体系是格挡来源 |
| 每当获得格挡时造成伤害 | 对格挡体系是扳机收益，并把防御端转为输出端 |

跨体系联动牌的记录重点不是“它能放进几个体系”，而是说明它在每个体系中分别扮演什么角色。

## 体系判定标准

可以按以下问题依次判断：

1. 是否有明确核心？
   如果只能用“这几张牌效果差不多”来描述，就不是体系。
   如果只能用“都影响同一类对象”来描述，也不是体系。

2. 是否有多张牌围绕核心产生不同职责？
   至少要能分出来源牌、收益牌、终结牌中的若干类。

3. 是否同时存在扳机触发和扳机收益？
   只有触发没有收益，或只有收益缺少稳定触发，都不足以判为成熟体系。

4. 是否覆盖多个端口？
   只覆盖输出端，或者只覆盖防御端，通常只是效果组。覆盖输出、防御、运转中的多个端口，才更像体系。

5. 是否存在持续收益或构筑动机？
   好的体系会让玩家想围绕它拿牌、删牌、升级、选择遗物或能力牌。

6. 是否能解释牌与牌之间的互相需求？
   例如“给易伤的牌”需要“吃易伤收益的牌”，“消耗源”需要“消耗触发收益”。如果牌之间没有互相需求，只是单卡并列，就不是体系。

7. 体系内每张牌是否有清楚定位？
   如果一组牌虽然看起来相关，但无法逐张说明它们是入口、燃料、奖励、补洞、连接还是上限牌，这个分组通常还不够清晰，应该重新拆分或降级为功能标签。

## 大体系、小体系、效果组

| 类型 | 判定 | 特征 |
| --- | --- | --- |
| 大体系 | 核心明确，触发牌和收益牌都足够，覆盖多个端口 | 可以独立承担一套牌的主要构筑方向 |
| 小体系 | 核心明确，但触发牌或收益牌数量少，且输出端、防御端、运转端中必然缺失某些端口 | 可以作为副轴或插件，但难以单独成为完整构筑 |
| 效果组 | 只是效果相似，没有共同核心，或没有形成扳机与收益的牌间需求 | 不应按体系分组，只能作为设计素材或功能标签 |

## 小体系的判定

小体系不是“牌少的体系”这么简单。它必须满足两个条件：

1. 核心仍然明确。
2. 因为触发牌、收益牌数量少，或端口缺失，无法独立成为完整构筑。

例如，某组牌都围绕一个明确卡牌标签触发，但只有输出收益，没有防御和运转，那么它可以是小体系。

如果牌数少，而且核心也不明确，那不是小体系，只是零散相似效果。

## 不应判为体系的情况

以下情况通常不算体系：

| 情况 | 原因 |
| --- | --- |
| 只有“高伤害牌” | 没有共同机制核心，只是数值定位相似 |
| 只有“抽牌牌” | 抽牌是功能，不等于体系 |
| 只有“获得格挡牌” | 防御效果相似，但没有共同资源或收益闭环 |
| 只有“保护盟友牌” | 作用对象相同，但没有独立扳机收益闭环 |
| 只有“随机生成牌” | 如果没有围绕生成牌的收益、消耗或标签互动，就只是效果相似 |
| 只有“费用作弊牌” | 减费、免费打出、获得能量可能是运转工具，但不一定形成体系 |
| 只有“终结牌集合” | 终结牌可以服务体系，但终结牌本身不构成体系 |

## 推荐记录格式

研究卡牌体系时，建议每个候选体系先写清楚下面这些字段：

| 字段 | 说明 |
| --- | --- |
| 核心 | 关键词、Power、资源、卡牌标签或触发条件 |
| 体系规模 | 大体系、小体系、效果组 |
| 输出端 | 哪些牌把核心转化为伤害 |
| 防御端 | 哪些牌把核心转化为生存 |
| 运转端 | 哪些牌提供抽牌、能量、减费、生成、回收等 |
| 扳机定义 | 这个体系中什么行为算触发扳机 |
| 扳机触发牌 | 哪些牌打出后会触发本体系扳机 |
| 扳机收益牌 | 哪些牌在本体系扳机触发或核心条件满足时获得收益 |
| 触发+收益牌 | 哪些牌同时制造扳机并从该扳机中获益 |
| 跨体系联动牌 | 哪些牌连接多个体系，并说明它在各体系中的角色 |
| 角色统计 | 触发牌、收益牌、触发+收益牌、跨体系牌的数量 |
| 体系内分类统计 | 机制引导牌、机制基础牌、机制核心牌、突破限制牌、机制中坚牌的数量 |
| 单卡定位表 | 逐张记录每张牌的体系内分类、扳机角色、端口、定位、独立性和依赖风险 |
| 来源牌 | 哪些牌负责制造核心资源或触发条件 |
| 收益牌 | 哪些牌从核心中获得额外收益 |
| 缺失端口 | 缺少输出、防御或运转中的哪些部分 |
| 结论 | 是否应作为体系写入体系文档 |

## 对铁甲战士分组的约束

按上述标准，铁甲战士中更像体系的方向包括：

| 候选方向 | 判定倾向 | 理由 |
| --- | --- | --- |
| 易伤 | 大体系 | 有明确状态核心，覆盖输出、部分防御和运转 |
| 消耗 | 大体系 | 有明确区域和触发核心，覆盖输出、防御、抽牌、能量 |
| 自损 | 大体系或中型体系 | 有明确触发条件，覆盖输出、力量、能量、回血和防御 |
| 格挡 | 大体系 | 有明确资源核心，覆盖防御、保留、翻倍和格挡转伤害 |
| 打击名称 | 小体系 | 有明确卡牌标签，但规模较小，端口不足 |

以下方向更适合作为效果组或功能标签，而不是体系：

| 候选方向 | 更合适的归类 | 原因 |
| --- | --- | --- |
| 单卡成长与终结输出 | 效果组 | 多数只是终结定位相似，没有共同核心 |
| 能量、抽牌与费用作弊 | 运转端标签 | 是服务其他体系的工具，不是独立核心 |
| 升级、变化与随机生成 | 功能标签 | 缺少统一资源或收益闭环 |
| 牌堆操控与自动打出 | 功能标签或小体系候选 | 需要进一步确认是否存在共同核心和收益闭环 |
| 攻击牌连动 | 小体系候选 | 有攻击牌标签核心，但需要检查是否能形成完整构筑，而不是普通攻击牌功能件 |
| 盟友承伤保护 | 防御端标签 | 只是格挡/防御牌的保护目标变化，不应单独列体系 |

## 最终原则

体系分组要服务于“理解构筑结构”，不是服务于“把所有牌都归类”。

如果某组牌不能回答“玩家为什么要围绕这个核心构筑”，就不要把它写成体系。它可以作为功能标签、设计素材或单卡用途记录。
